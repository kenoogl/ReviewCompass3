## 3. 採用する確認方法

1. 現在有効な要求、採用済み設計判断、開発方針から、変更、廃止または緩和された振る舞いを特定する。
2. その振る舞いについて、現在の設計に適合する実装例または入力例を、リポジトリ外の一時複製に用意する。
3. 現在の設計だけでは正しさを一意に決められない場合は、実行者が補わず`判断不能`として利用者へ戻す。
4. 正しい実装例の状態で、観測commitの現役全試験を単独コマンドで実行する。
5. 失敗した試験だけについて、正しい実装例との因果関係と、試験が要求する古い期待結果を確認する。
6. 次の三点をすべて確認できた試験だけを、修正、削除または使用停止の候補にする。
   - 実装例が採用済みの現在設計に適合する。
   - 試験の失敗原因がその実装例にある。
   - 試験が現在は不要になった古い期待結果を要求している。
7. 失敗しない試験と、矛盾を実証できない試験は現状維持とする。

観測時点の1,728件は実行対象の集合を照合する値であり、恒久的な合格件数や削減目標にしない。
全試験を人が詳しく読まず、全Decision、全参照、全呼出し先を一覧化または分類しない。
