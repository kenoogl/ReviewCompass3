四領域の責務を次に固定する。

| 領域 | 第2段で選ぶ責務 |
| --- | --- |
| 履歴保存 | 意味的に完結したコミット、重要判断、承認・入力・結果、原資料と派生物、失敗・取消し・置換を復元できる形で残す |
| 開発コード管理 | 実装前検索、再利用判断、公開入口と呼出し関係からの到達確認、廃止理由と後継の履歴を扱う |
| テストコード管理 | 恒久試験、作業限定試験、実験試験を分け、公式入口が結果記録を伴って合否を返す |
| レビュー | 固定範囲、危険度相応の材料、作業担当と異なる根拠、一回の独立確認と一回までの修正後確認を扱う |

評価上限は次のとおりとする。

- 候補は一領域につき各前身から最大一件、合計最大4件、四領域全体で最大16件とする。
- 候補の単位は失敗条件、小部品または一つの経路とし、前身の仕組み全体を一候補にしない。
- 第1段の現役入口と未確認入口、固定入力から直接到達する最も小さい前身候補だけを扱う。
- 一領域につき、選定候補の正規入口から代表的な正常処理を一例だけ確認する。
- 未修正の重大な欠陥12件は、選定候補から到達するものだけを参照・呼出し検索で特定する。12件の
  一括レビューまたは一括修復は行わない。

Python 3.13への移行は、テストコード管理の正規入口が依存する実行環境の独立候補として評価する。
現行のPython 3.9固定、実際の実行版、Python公式の保守状況、依存関係への影響を確認し、次のいずれかを
採用表候補へ記す。

- 第2段で選ぶ試験入口の前提なので、別の軽量作業票による移行が先に必要。
- 第2段完了の前提ではないが、期限を示した後続作業が必要。
- 移行不要。不要とする実測根拠を示す。

本作業ではPython、仮想環境、依存関係、設定を変更しない。

次は対象外とする。

- コード、試験、設定、計画、既存記録の修正または削除。
- 前身コードの複製、一括移植、全守り役コードのレビュー、重大な欠陥12件の一括修復。
- 新しい大域台帳、検査器、状態機械、作業契約基盤の作成。
- 外部送信、認証、配置更新、管理範囲外への書込み、別リポジトリの変更。
- 第3段以降、製品本線、正式な作業契約の開始。

## 5. 機械で確認する事実と、使用する正規入口

次をLLMの手集計にせず、Git、`rg`、Python標準機能および既存の正規入口で確認する。

- 基準コミット、固定入力、資料目録の各参照先とSHA-256。
- 候補の由来、固定コミットまたは記録、現在の案内・設定・公開入口からの到達性。
- 候補から未修正の重大な欠陥12件の対象範囲への参照・呼出し関係。
- 履歴保存はGitから一件の作業票、判断、結果を再読込できること。
- 開発コード管理は一つの既知入口から実装と直接呼出し先を検索できること。
- テストコード管理は
  `python3 -m tools.development.policy_test_runner --suite full --receipt <一時path>`を単独実行し、
  終了コード、結果記録、Python版、試験件数、失敗件数を再読込できること。
- レビューは本作業の独立完了レビューを代表正常処理とし、作業票、固定材料、判定、利用者判断境界を
  一続きで確認できること。追加の重複レビューは行わない。
- Python移行候補は現行設定、実行版、依存関係名、Python公式の保守情報の取得日と参照先を確認する。
  公開情報の読取り時にプロジェクト内容を送信しない。

正規入口から正常処理を実行できない候補、結果記録を再読込できない候補、案内から発見できない候補は
`採用候補`にしない。検証のためだけに恒久ツールを追加しない。

## 6. レビューで判断する事項

開始時に、操縦役と利用者が次を確認する。

- 四つの前身の解釈。
- 四領域の責務。

- Python 3.13移行をテストコード管理の独立候補として評価し、移行自体は別作業とすること。

一回だけ、候補集合の範囲、五条件への適合、機械証拠、重大な欠陥への依存、正常処理、過去の複雑さを
過剰移植していないことを確認する。

完了レビューの判定と止める指摘は上位計画第6章に従う。技術的な`verified`だけで採用または第2段完了に
せず、利用者が採用、使用停止、保留を最終判断する。

## 7. 停止条件と完了条件

開始には、この作業票のコミット、利用者による開始確認、基準コミットと固定入力SHA-256の一致を要する。

上位計画第13章の停止条件に加え、次の場合は評価結果を推測で埋めず停止する。

- 四つの前身または四領域の責務について、開始確認と異なる解釈が必要になった。
- 候補の採否に、固定範囲外の原文、別リポジトリの全探索、非公開保存物が不可欠になった。
- コード、試験、設定、設計または既存記録を変更しないと評価を続けられない。
- すべての候補が重大な欠陥へ依存し、代替、使用停止または保留だけでは四領域の入口を提案できない。
- Python移行を実施しなければ試験入口を評価できない。

作業単位の完了条件は次のとおりである。

- 成果物一件が基準コミット、作業票、固定入力へ結び付く。
- 四領域すべてに責務、候補、五条件の判定、提案状態、根拠、未確認範囲がある。
- 候補は各領域最大4件、全体最大16件で、選定候補の代表正常処理が各領域一例だけ確認される。
- 各領域に正規の現役入口となり得る`採用候補`が一件ある。重大な欠陥へ依存する候補は採用候補にしない。
- 各採用候補は案内文書から発見でき、主要部品まで機械的に接続される。
- Python 3.13移行候補が、前提作業、期限付き後続または不要のいずれかへ根拠付きで分類される。
- 対象外変更がなく、成果物が意味的に完結したコミットへ固定される。
- 一回の独立完了レビューが`verified`である。

その後、利用者が四領域の採用、使用停止、保留と第2段完了を別に判断する。
