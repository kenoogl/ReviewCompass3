## 3. 境界1：副作用のない比較核

### 3.1 利用者向けの意味

二つの入力bytesを厳格に検査し、4比較、欠落、未参照、件数、内容識別値、人の判断一覧を同じ入力から同じ結果へ整理する。

### 3.2 先に固定する失敗試験

- `equals`：同じ値で成立、値違いと型違いで不成立。
- `not_equals`：値違いで成立、同じ型・同じ値で不成立。
- `contains_all`：包含で成立、不足と設計値非配列で不成立。
- `contains_none`：非交差で成立、交差と設計値非配列で不成立。
- 同じ`subject`がない条件は`missing`、条件から未参照の全事実は一度ずつ残る。
- 全条件成立時も`pending_human_decision`で、全条件を人の判断一覧へ残す。
- 真偽値と整数を別型として扱う。
- object項目順、事実順、条件順、文字列配列順だけの差で出力bytesとSHA-256を変えない。
- 一値変更で値、入力、照合結果のSHA-256を変える。
- root、事実、条件の同名JSON項目と、escape復号後の同名項目を復号時に拒否する。
- 未知項目、重複ID・subject、不正識別子、禁止値型、空配列、件数上限超過を拒否する。
- 正常結果の項目集合、並び順、null、件数、固定語彙を完全一致で確認する。

### 3.3 最小実装

- `DesignAcceptanceStop`は`reason`と`source`の固定値だけを保持し、入力値や例外本文を保持しない。
- JSONは項目対を保持する復号hookで全objectの同名項目を検出し、通常dictへ変換する前に停止する。
- 値の型検査は真偽値を整数より先に判定し、浮動小数点、null、object、入れ子配列を拒否する。
- 検査済み文字列配列を昇順へ、事実をsubject・fact ID順へ、条件をcondition ID順へ正規化する。
- Pythonの緩い`==`を使わず、JSON型と値の双方で完全一致を判定する。
- 4比較は契約§6.5の成立・不成立を個別分岐で実装する。
- 正準JSONはUTF-8、BOMなし、項目名順、空白なしとする。
- 正常結果には入力自由値を含めず、安全な識別子、ID、固定語彙、件数、SHA-256だけを含める。

### 3.4 不変条件

- 形式不正を照合結果へ変換しない。
- `missing`と`contradicted`を混ぜない。
- 条件同士の競合を設計側矛盾へ混ぜない。
- 満たした条件を自動受入しない。
- 入力配列の順だけを意味として扱わない。
- 外部作用を行わない。

## 4. 境界2：利用時点の安全読取り

### 4.1 利用者向けの意味

利用者が明示したroot内の異なる通常file二件だけを、途中のsymlinkや読取り中の差替えを受け入れずに読む。

### 4.2 先に固定する失敗試験

- 相対root、相対file、字句上root外、`.`・`..`・空構成要素、同じ二fileを拒否する。
- file system起点からrootまでの途中要素、root自身、rootからfileまでの途中要素、file自身のsymlinkを各一件ずつ拒否する。
- root自身だけへ`O_NOFOLLOW`を使い途中symlinkを許す欠陥を検出する。
- directory、名前付きpipe、socketなど通常file以外を拒否する。
- 読取不能、262,144 bytes超過、読取り前後のsize・機器番号・inode変更、実読取りbyte数不一致を拒否する。
- rootまたはfileの要素別非追跡openを使えない場合に停止する。
- 読取り処理がfile、directory、権限、環境、Gitを変更しない。

### 4.3 最小実装

- 絶対pathを純粋な構成要素へ分け、`/`からrootまでをdirectory file descriptorで一要素ずつ開く。
- 各directoryへ`O_DIRECTORY | O_NOFOLLOW`相当、最後のfileへ`O_RDONLY | O_NOFOLLOW | O_NONBLOCK`相当を使う。
- 入力fileの字句構成要素がroot構成要素を完全な先頭列として持つことを確認し、rootからの残りを相対openする。
- open後に`fstat`で通常file、size、機器番号、inodeを確認する。
- 上限より1 byte多く読む。読取り後に`fstat`を再実行し、種類、size、機器番号、inode、実読取りbyte数を照合する。
- 二fileの機器番号とinodeが同じなら拒否する。
- descriptorは成功・失敗の全経路で閉じる。

### 4.4 不変条件

- `resolve()`後の文字列比較だけで安全としない。
- 事前確認したpathを名前で開き直さない。
- 途中symlinkを一つも追わない。
- 入力pathを結果または例外へ含めない。

## 5. 境界3：正式命令入口と安全表示

### 5.1 利用者向けの意味

### 5.2 先に固定する失敗試験

- 正式引数一式で、核結果と完全一致する正準JSON一件、改行一つ、空の標準エラー、終了コード0を返す。
- 引数不足、未知・重複引数、未知操作、相対pathを入力読取り前に`invalid_arguments`または`invalid_path`で止める。
- 設計側のsize、UTF-8、schema不正は`source: design`、受入条件側は`source: acceptance`を返す。
- 入力fileを特定できない読取り失敗と内部失敗は`source: none`を返す。
- 内部例外へ秘密候補、絶対path、入力値を入れても、固定した`internal_failure`だけを返し、標準エラーを空にする。
- 正常・停止出力に入力自由値、絶対path、例外本文、入力抜粋がない。
- 入口からfile書込み、通信、外部process、Git、環境値解決、権限変更、入力外探索を呼ばない。

### 5.3 最小実装

- 独自の小さい引数検査で、許可する引数名と個数だけを受ける。自動usage表示で入力値を出さない。
- 境界2で二入力を読み、境界1へ渡す薄い入口とする。

### 5.4 不変条件

- path、入力自由値、例外本文を出力しない。
- 停止時に部分的な成功結果を返さない。
- 命令入口で比較規則やschemaを追加しない。
