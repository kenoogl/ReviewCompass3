## 1. 目的

観測対象コミットにおけるReviewCompass3の現在位置と主要な利用経路を一枚の表にする。
各入口を`現役`、`使用停止`、`未確認`、`履歴のみ`に分け、部品間の接続方法と、案内文書から
正規入口までの導線を示す。この作業では修復せず、第2段が判断できる現在位置だけを作る。

## 2. 入力と根拠

履歴上の変化は開始コミットから観測対象コミットまでとする。全コミットを精読せず、件名と変更パスを
機械列挙する。資料の母集合は次に限定する。

1. 観測対象コミットでGitが追跡する全パスの名前と、対象期間の変更パス。
2. `README.md`、`docs/README.md`、`AGENTS.md`、`CLAUDE.md`、`TODO_NEXT_SESSION.md`。
3. `docs/current/`、採用済み立て直し計画と判断、初期開発チェックリスト、開発方針、レビューと操縦役の入口文書。
4. `pyproject.toml`の実行入口と、それが直接参照するモジュール、設定、案内文書。
5. 上記から直接参照される判断・実行記録と、主要入口の直接の呼出し・取込み関係。

生のセッションログ、リポジトリ外の非公開保存物、全記録の本文は含めない。個別資料を追加する場合は、
成果物に参照理由を記す。

分類語彙は次のとおりとする。

| 分類 | 基準 |
| --- | --- |
| `現役` | 現在の案内、公開入口、設定、主要経路から利用され、使用停止の判断がない |
| `使用停止` | 処理は存在するが、再確認または修復まで入口から使わない |
| `未確認` | 存在または参照は確認できるが、現在使ってよい根拠が不足する |
| `履歴のみ` | 現在の入口と主要経路から使わず、過去の経緯だけを保持する |

静的な参照だけで`現役`と断定せず、根拠不足は`未確認`にする。

## 3. 作業範囲と対象外

作業範囲は、製品本体、最小信頼基盤、LLM連携、実験、履歴の主要入口と主要経路である。接続を
`機械接続`、`人による一時的な中継`、`未接続`、`未確認`に分け、案内と実入口の一致、現行計画、
初期開発チェックリスト、TODOの古い記述または競合を確認する。

次は対象外とする。

- コード、試験、設定、計画、TODO、既存記録の修正または削除。
- 入口の修復、試験整理、重大欠陥12件の修復、第2段以降の判断。
- 全コミット、全コード、全試験、全記録の精読または再レビュー。
- 新しい管理ツール、台帳、検査器、状態機械の作成。
- Claude、外部API、ネットワーク、外部送信、非公開保存物の読取り。

## 4. 期待する成果

成果物は次の一ファイルだけとする。

```text
records/development/2026-08-12-stage1-current-position-and-active-routes-v1.md
```

成果物には、対象と方法、五領域の要約、主要経路表、古い記述または競合、第2段へ渡す未確認範囲、
機械処理のコマンド・終了コード・件数・内容識別値を含める。主要経路表は、領域、案内文書、正規入口、
主要部品、設定・保存先、接続方法、分類、根拠、未確認事項を持つ。

別の全量台帳や補助記録は作らない。一時出力はリポジトリ外へ置き、成果物には再現に必要な情報だけを残す。

## 5. 機械で確認する事実と、使用する正規入口

追跡パス、対象期間のコミットと変更パス、`pyproject.toml`の実行入口、参照パスの存在、Git内参照、
SHA-256、作業前後のGit状態と変更パスは、Git、`rg`、Python標準機能、既存の安全な読取り入口で
機械確認する。LLMが目視で集計せず、新しい恒久ツールを作らない。

実行しなければ使用可能か判定できない入口は実行せず、`未確認`にする。作業の正規入口はこの作業票、
完了レビューの入口は採用済み計画第6章とする。

## 6. レビューで判断する事項

開始前は、操縦役と利用者が対象期間、資料の母集合、分類語彙、対象外、成果物、完了条件を確認する。
独立した開始前レビューは追加しない。

作業後は、作業担当と異なる実行単位が一回だけ、資料範囲、各分類のGit根拠、接続方法、入口導線、
対象外の維持、第2段の入力としての有用性を確認する。不明なものを推測で分類してはならない。

読み取りと文書作成だけなので、全試験、変異検査、障害注入、新しい反証試験は行わない。止める指摘は
`docs/development/work-review-protocol.md`第11.1節の四種類だけとし、修正後確認は必要な場合も一回とする。

## 7. 停止条件と完了条件

開始には、この作業票のコミット、利用者による開始確認、観測対象コミットと上位計画SHA-256の一致を要する。

即時停止は採用済み計画第13章の五条件だけとする。その他の不足や曖昧さは作業を止めず、`未確認`または
後続候補として成果物へ記す。

作業単位の完了条件は次のとおりである。

- 成果物一件が観測対象コミットと資料の母集合に結び付く。
- 主要経路が四分類のいずれかを持ち、各行に根拠または未確認理由がある。
- 接続方法、入口導線、古い記述または競合が示される。
- 機械処理の結果を再確認でき、対象外変更がない。
- 成果物が意味的に完結したコミットへ固定され、一回の独立完了レビューが`verified`である。

第1段の完了は、その後に利用者が別に判断する。技術的な`verified`だけで段完了にしない。
