## 3. 作業範囲と対象外

作業範囲は次に限定する。

1. 401件の試験識別子から、ファイル、試験名、引数付き識別子を機械抽出する。
2. Git履歴、製品コード、設定、証跡、対応表、入口からの参照を読み取りで列挙する。
3. 同じ利用者、要求、機能、履歴資料、共有境界を持つ候補を意味群へまとめる。
4. 各群について、件数、対象ファイル、境界根拠、主な参照先、危険境界、次の検査方法を短く示す。
5. 承認済み一件が属する群を示し、`削除判断済み・実施待ち`として区別する。

対象外は、試験、製品コード、設定、証跡、対応表の変更、削除・統合、必要性の一括裁定、全試験、
変異検査（意図的に欠陥を入れて検出能力を確かめる検査）、新しい台帳・検査器・試験の追加、
第3段完了、外部送信、push、履歴書換えである。

## 7. 停止条件と完了条件

次の場合は停止する。

- 401件一覧の欠落、重複、基準の不一致が見つかった。
- 分類にコード、試験、設定、証跡、対応表の変更が必要になった。
- 外部送信、不可逆操作、未承認の意味変更が必要になった。
- 一つの群の判断から別の実装や修正へ連鎖しそうになった。

次をすべて満たしたとき完了候補とする。

- 401件の過不足なし、重複0件を機械確認した。
- 意味群の境界と、その根拠を説明した。
- 危険境界と、役割判定に不足する材料を隠していない。
- 最初に詳しく検査する一群を一つだけ提案した。
- 試験、製品コード、設定、証跡、対応表を変更していない。
- 独立完了レビューとClaude変更点確認へ渡す固定材料を作れる。
