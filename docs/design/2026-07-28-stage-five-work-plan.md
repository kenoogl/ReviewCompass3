# 第5段：designとブートストラップ適合性監査

## 目的

承認済みintent、9機能37要件、464原子的義務、23機能境界relationを
設計判断と受け入れ試験へ結線する。先行実装は固定commitの証拠だけから
`conformant`、`adapt`、`replace`、`defer`へ分類し、挙動へ要件・設計を
合わせない。

## 作業単位

1. 固定入力と設計・適合性監査SchemaをTDDで確定する。
2. 9機能の設計、代替案、境界、失敗処理、受け入れ試験を作る。
3. 37要件すべてへ設計受け先と受け入れ試験を結線する。
4. 固定commitの実装・テスト証拠から37要件を分類する。
5. 3観点で独立レビューし、未解決0件なら利用者承認候補を作る。

## 責務原則

- LLMは文章読解、意味的整合性、所見候補の提示を担う。
- 機械処理は列挙、Digest、Schema、参照、被覆、状態遷移、保存を担う。
- Humanは外部送信、Finding採否、設計・段完了を判断する。

## 完了条件

- 全37要件に設計受け先と受け入れ試験がある。
- 23境界relationが設計間で相互に一致する。
- 37要件が4分類のいずれかへ証拠付きで一意に入る。
- conformantは実装・テストの両証拠を持つ。
- 未定義参照、未被覆、競合、未解決レビュー指摘が0件である。
