# Work 4A LLM分析コンテキスト設計メモ

状態：`discussion_memo`
対象：Work 4A Reusable Routine Ledger
関連：`docs/design/2026-08-04-work-4a-rebuild-design-v3-1-amendment.md`

これはLLMによるDisposition Proposalを実装または承認するものではない。966件のRoutine Profileを
判断材料として使う際の、LLMへの情報提示量と提示順序に関する検討メモである。

## 結論

LLMの判断精度を上げるために必要なのは、情報量そのものではなく、判断に関係する情報を必要な時に
過不足なく提示することである。全source treeを毎回渡す方式は採らない。

## 三層の提示方式

### 第1層：全体の機械一覧

Routine Profileの機械抽出値を用いる。目的は、分析対象のgroupまたはroutineを選ぶことである。

- symbol ID、種別、規模、参照数
- 構文的操作痕跡
- AST構造一致group
- 機械による責務分類の提案

この層だけで最終の処置labelを決めない。

### 第2層：判断カード

対象routineごとに、次の情報を構造化して提示する。

- 役割の候補
- 入力と出力
- 呼出元と呼出先
- raise・catch関係
- 構文的操作痕跡
- 関連Test
- 構造一致および意味的な重複候補
- 処置labelの候補、根拠、不確実性、人が確認すべき点

LLMが出す役割・重複候補・処置labelは、すべて非権威の提案とする。

### 第3層：限定した周辺コード

判断カードだけで結論を出せない場合に限り、次を追加する。

- 対象routineの本文
- 直接の呼出先
- 直接の呼出元
- 比較対象となる類似routine
- 関連Test

プロジェクト全体のsourceを一括して渡さない。対象を広げる条件と、追加した範囲を記録する。

## labelごとの重点情報

| label候補 | 主な確認材料 |
| --- | --- |
| `reuse` | 呼出元の多さ、公開性、Test、入出力の安定性 |
| `extend` | 責務の一貫性、既存利用の不足、関連する特殊ケース |
| `merge` | 入出力、例外、呼出元、操作痕跡、意味的重複の比較 |
| `split` | 規模、分岐、return、例外、複数の操作痕跡、責務の混在 |
| `as_is` | 小さく限定的な責務、安定した利用、重複候補の不在 |

## 規律

- 機械抽出値とLLMの意味分析を混同しない。
- 情報不足ならLLMはlabelを強制せず、`human_review_required`とする。
- LLM提案はHuman Decisionの代わりに使わない。
- source本文、対象範囲、生成元、根拠参照を追跡可能にする。
- このメモの内容を採用する場合は、v3.1設計の改訂または別Decisionで承認する。
