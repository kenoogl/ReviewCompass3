## 3. 三案比較と過剰対応

【判断】案Aは製品コード、新機構、新しい設定を作らず、削除判断済み一件だけを扱う最小案である。案A、案B、
案Cは、単純さ、処理時間・記憶量、頑健さ、変更範囲、保守負担、戻しやすさを比較しており、三案比較の形式は
AGENTS.md §4を満たす。

【判断】案Bには新しい台帳、検査器、試験、強制関門の追加はなく、本質から外れた過剰修正の混入はない。
ただし、案Aを不採用とする理由だけでは、後述の現役対応を壊す案Bを選べない。問題の解消に新機構は不要で、
まずG11三件を案Bから外すか、現行要求対応の扱いを別の意味的裁定として明示する必要がある。

## 4. G04二件と履歴対応表

【実測】G04の二試験は、2026-08-11の宣言対応表の32要求IDとRED証跡の三文言を読む。製品コード、設定、
正規入口がこの二試験を現在動作の保証として参照する箇所は見つからなかった。宣言対応表とRED証跡は
commit `8cdac45`から回復でき、現在ファイルも固定物と一致するという先行照合とも矛盾しない。

【判断】宣言対応表を当時の履歴資料として変更せず、今回の現在ゲートにしない扱いは妥当である。履歴中の試験名を
現在の試験集合へ追従させると、当時の対応関係を書き換えることになる。ただし、この宣言対応表と、次節の
`tests/test_pilot_collaboration.py`にある現在実行される`TRACEABILITY`は別物である。後者まで履歴資料として
無視することはできない。

## 5. 止める指摘

【実測】`tests/test_pilot_collaboration.py`の`TRACEABILITY`は、削除予定のG11三試験を次のように7回参照する。

| 現行要求ID | 削除予定試験への参照 |
| --- | ---: |
| `NG-PC-007` | 2件 |
| `ST-PC-001` | 2件 |
| `OUT-PC-004` | 3件 |

同ファイルの`test_requirement_traceability_covers_all_26_ids`は、四つの現役試験ファイルから試験関数名を
構文木で列挙し、`TRACEABILITY`の全参照が実在することを毎回検査する。現在は未定義参照0件だが、案Bの
三試験だけを除いた状態をメモリ上で再計算すると、三試験名すべてが未定義参照になる。

【実測】共通入口`docs/development/prompts/pilot-collaboration-run.md`は現在もv6指示書を正本として直接参照し、
AGENTS.mdとCLAUDE.mdは同共通入口へ接続している。v6の`NG-PC-007`、`ST-PC-001`、`OUT-PC-004`は実在し、
現在の`TRACEABILITY`が上記三試験をその証拠として結び付ける。

【判断】したがって、G11三試験を「役割終了」として二試験ファイルだけから削除してよいとは確認できない。
三試験の補助処理が製品コードにないことと、三試験の識別子が現行要求対応に使われないことは同じではない。
現行要求対応を維持するなら三試験を残す必要がある。対応を廃止または置換するなら、
`tests/test_pilot_collaboration.py`と要求証拠の意味的裁定が必要となり、計画の二ファイル限定を超える。

止める指摘はこの一系統である。

## 6. G11専用要素と件数

【実測】`ALLOWED_PATHS`、`_git`、`_commit_changed_paths`、`_is_followup_record`、
`_implementation_paths_since_base`、`_initialize_test_repository`、`_commit_test_change`、`subprocess`の取込は、
同じ試験ファイル内では三試験から到達する処理だけに使われる。三試験を正当に削除できる場合に、これらを同じ
意味単位で除く境界は妥当である。別ファイルにあるのは補助要素の利用ではなく、三試験名の要求対応参照である。

【実測】14件から指定五件を除く収集件数の算術は9件である。また、基準1,739件以後に試験変更がないため、
指定五件だけを削除した収集件数は1,734件になるという計数自体は整合する。しかし、現在の
`TRACEABILITY`を変更しない限り`test_requirement_traceability_covers_all_26_ids`が失敗するため、計画の
「1,734件成功、失敗0」は成立しない。件数と合否を取り違えている。

【判断】計画は、既承認一件と新たな承認四件を分け、案B、保証廃止、変更範囲の三点をHuman判断へ返している。

このレビューの止める指摘を反映した修正版と、必要なら要求対応を廃止・置換する意味的選択肢を先に示す必要がある。
