## 1. 利用者の判断

【記録】利用者には、案Cを次の製品機能として説明した。

- 利用者が許可したSession記録一件を、機微情報用の領域へ保存する。
- 正式な読取り専用入口が作る結果から、保存を許した項目だけを別領域へ保存する。
- 確定した派生結果だけを再読込みする。
- 保持期限後は通常読込みを拒否する。
- 削除対象と件数を示し、利用者の確認後に一記録だけを削除する。
- 書込みや削除が中断しても、成功を推測せず安全に再試行する。

【記録】利用者には、案Cの実装準備と実装開始を承認するか、採用済み契約だけを保持するかの二択を提示した。
利用者は次のとおり選択した。

> １

【判断】この選択を、採用済み契約v3に従う案Cの実装準備と実装開始の承認とする。

## 2. 承認した実装の方向

【判断】次の小さい構成を承認する。

1. 現在の正式な読取り専用入口へ、安全な結果を画面表示せず値として返す小さい公開関数を加える。
2. 一件だけを、利用者が明示した二つの保存領域へ保存・再読込み・削除する専用の保存処理を加える。
3. その保存処理を呼ぶ製品用の実行入口と、配布後に使える実行名を加える。
4. 契約の正常例、失敗例、境界例を、実装より先に試験へ固定する。

【判断】利用者の承認だけで直ちに製品コードを変更しない。まず、変更するfile、先に失敗させる試験、
停止条件、独立確認方法を小さい実装作業票へ固定し、新しい独立担当の開始前レビューで`開始可`となった後にだけ
製品コードを変更する。

## 3. 実装範囲の上限

【判断】実装作業票は、次の意味的に完結した範囲を上限とする。

- 既存の正式な読取り専用入口の値受渡し。
- 一件専用の新しい保存処理。
- 一件専用の新しい製品入口。
- `pyproject.toml`への実行名一件。
- 上記だけを直接確認する試験と、実施・レビュー記録。

【判断】G26全体、G30、暫定の製品計画、要求候補を正式化しない。既存G26の個別処理を使う必要が判明した場合は、
その処理だけを再評価し、作業票の範囲を無断で広げない。

## 4. 実装順序

1. 現行コードと既存試験から、変更候補fileと現在の動作識別値を固定する。
2. 実装作業票を作成し、独立開始前レビューを行う。
3. `開始可`の場合だけ、契約から導いた失敗試験を追加し、実装なしで失敗することを確認する。
4. 試験を変えずに最小実装を行う。
5. 対象試験、影響する既存試験、正規の全試験を実行する。
6. 中断、改変、権限、symlink、二領域不一致、誤削除の高危険度境界だけを、故障を意図的に起こす確認と独立完了レビューで検証する。
7. 製品としての受入、正式・安定表示、後続機能は別の利用者判断へ戻す。

## 5. 停止条件

次の場合は承認範囲を広げず停止する。

- 採用済み契約の責務、保存内容、状態、削除意味または安全上の限界を変える必要がある。
- G26全体、G30、探索、複数記録処理、自動削除、外部送信、networkまたは外部processが必要になる。
- 既存の正式な読取り専用入口の正常出力、停止出力、終了区分、正式・安定表示を変える必要がある。
- 変更範囲外の既存試験を書き換えなければ実装できない。
- macOSで所有者限定の権限、symlink非追跡、repository外の二領域分離を守れない。
- 独立開始前レビューが`開始可`以外になる。
