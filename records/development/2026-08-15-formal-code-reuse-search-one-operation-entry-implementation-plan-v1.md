## 1. 機能と用途

既存の機械処理を決めた順に一回で呼び、確定ローカルcommitから、現在コードの観測、処理一覧、比較候補、
作業別の再利用候補、外部保存記録、project内証明書、最終結果までを生成する開発支援入口である。
新しい製品機能を実装する前に、既存コードの重複と再利用候補を確認するために使う。

## 2. TDD開始前の実装境界

- 入力：変更のないローカルcommit、現行source universeとfreshness policy、一件以上の作業別検索宣言、
  新規の証明書path、ローカル開発データ領域。
- 利用者価値：一回のcommandで、途中の呼び忘れや順序違いなしに、同じcommitへ結び付いた検索結果を得る。
- 実装がない場合の主要な失敗理由：正式な一操作入口が存在しない。
- 最小実装：既存の`capture_committed_observation`、Routine Profile v3、Comparison Discovery、
  `search_existing_routines`、`externalize_reuse_search_record`、`gate_check_attested`を順番に呼ぶ薄い入口。
- 先取りしない責務：処理の新しい抽出算法、比較算法、ライフサイクルの自動裁定、再利用方法の自動裁定、
  中央一覧、自動commit、push、外部repository同期、TDD境界確認。
- 完結性：一つのcommit観測と、一つの計画に含まれる全検索結果をまとめて返す。二検索を別commandに分けない。
- 戻し方：新入口、対象試験、作業別検索計画、方針追記を除けば既存処理は変更しない。

## 4. 機械処理と人の判断

入口が機械処理するのは、commit状態、対象集合、内容識別値、処理一覧、比較候補、宣言別検索、証明書、
鮮度、件数、終了結果である。正式・暫定・使用停止の区分と、再利用・拡張・分離の採否は決めない。
結果には両方が人の裁定待ちであることを明示する。

## 5. TDDと完了条件

最初に、外部repositoryを持たない変更なしcommitから複数検索が一回で完了する例、未commit状態、空の対象path、
既存証明書path、Git外の作業場所を試験する。入口がなければ失敗することを確認後、試験を変更せず最小実装する。
