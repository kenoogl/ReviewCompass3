## 0. 測定（すべてcommand出力の転記）

```text
$ git log --since="2026-08-10 00:00" --format='%h' | wc -l
106
$ # code/testを含むcommit数
23
$ # recordのみのcommit数
83
$ git log --format='%h' 431dd7b..HEAD | wc -l   # 組C RED以降のcommit
8
$ # うちcode/testを含むもket
0
```

本日のcommit 106件のうち**23件がcode/test**、**83件がrecordのみ**。
組CのRED（`431dd7b`）以降の8 commitで**code/testに触れたものは0件**であり、
group Cの5件は着手途中で停止している。

## 1. 原則：レビューの終了条件は対象の種類で決まる

| 型 | 対象 | 判定基準 | 終了条件 |
| --- | --- | --- | --- |
| 型1 | 守り役code（他の成果物の合否を決める） | 反証が不成立になるか | **機械的**：反証が拒否され、拒否時に副作用が残らず、公式全Test合格 |
| 型2 | 通常のcode | 受入条件を満たすか | **機械的**：Test合格 |
| 型3 | 範囲固定（実装前の文書） | 境界が一意か、上流と矛盾しないか | **回数制**：改訂2回まで。3回目はHuman裁定へ上げる |
| 型4 | 散文（自己申告・原因分析・規約・整理案） | 記載した事実が独立再現するか | **1周のみ**。2周目以降の指摘は`改善候補`へ回し、その場では直さない |

**本日の失敗は、型4を型1と同じ基準で扱ったことである。** 型1は反証を実行して真偽が
決まるため閉じる。型4には実行できる反証が無く、判定は事実上「Reviewerが穴を
思いつけないこと」になるため閉じない。実際、原因分析は2周、規約は3周レビューし、
いずれも新しい指摘が出続けた。

## 2. 実証済みの手順（本日、効果が機械確認できたもの）

### 2.1 巻き添え防止（範囲固定の前に機械実行）

対象fileの**現在のSHA-256で全文検索**し、Digestを固定しているrecord・testを洗い出す。

```text
$ # tools/先頭40 moduleのうち、現在Digestがrepository内の別fileに在るもの
32
$ grep -rln "read_bytes()).hexdigest()\|_sha256(" tests | wc -l
35
$ # うちpin期待値との比較を併せ持つもの
12
```

**効果の実証**：Codexの規約C有効性判定（`061cb1c`）は、Pilotの違反commit `f8c01b5`の
実変更8件と当時のscope宣言7件を突き合わせ、**範囲外の契約record 1件を機械検出**した。
「防げるはず」ではなく「防げた」実績である。

### 2.2 検査の正しさ（実装前）

反証testが**狙った欠陥そのものを理由に失敗している**ことを確認する。修正前の実装へ
当てても失敗することまで確かめる。group A完了レビューv1の`F-CG-COMP-001`は、
Digest不一致という別理由で失敗していたtestを合格扱いにしていた実例である。

## 3. 未確定のまま運用するもの（完璧を待たない）

| 項目 | 状態 | 扱い |
| --- | --- | --- |
| 受入条件の三点セット（規約C項目8） | 正例が既知の偽陽性境界を踏む条件が無い（`RC-EFF-001`） | 限界を記録したまま運用 |
| 実物迂回の反証（規約C項目10） | 最低1件のみ要求。変種の網羅は義務でない（`RC-EFF-002`） | 限界を記録したまま運用 |
| 利用者の正当な選択と誤りの区別（group B W2型） | 原理的に判定不能 | 限界として宣言 |
| `risk low`の定義 | 規約に規定が無い。実績3件・うち1件要修正 | データを集めてから定義（Human裁定済み） |

**規約を完成させてから使うのではなく、不完全と分かっている規約を使って実測する。**
Humanの「risk lowはデータを集めてから定義」を規約全体へ広げた形である。

## 4. 数値の扱い

**LLMは意味分析・説明・文章化に限定し、件数・Digest・file数を目視で裁定しない**
（上流正本：`docs/design/2026-08-03-session-transcript-eventual-preservation-design.md` §9）。
recordへ数値を書くときは、必ずcommandを実行し**出力をそのまま転記**し、再現commandを
併記する。Pilotが手書きした数値は2周連続で誤りが出た（16→撤回、23→実は12、
停止3回→実は2回）。

## 5. 規約の有効性の測り方（レビューではなく実験）

規約A・B・Cが効いたかは、**次の作業単位で指標が下がるか**で判定する。
レビューで「穴が無いこと」を確かめようとしない。

本日の基準値（守り役後追い修正4単位＝E/A/B/C）：

| 指標 | 値 |
| --- | ---: |
| scope改訂commit | 7 |
| 範囲レビュー要修正 | 4 |
| 完了レビューblocking | 3 |
| 実装中の停止（回数／理由） | 2／3 |

group C・group Dの2単位で同じ指標を測り、下がらなければ規約の設計が誤っていたと
判断する。

## 6. 適用と留保

- 本整理は`work-review-protocol.md`および`role-neutral-pilot-review-collaboration.md`を
  **置き換えない**。両文書への反映は、進行中の単位を閉じてから別単位で行う。

  現行運用より厳しい。**この上限が妥当かは実測で決める**（§5の指標に含める）。
