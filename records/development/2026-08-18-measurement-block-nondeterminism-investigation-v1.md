# 測定ブロック非決定的欠落の根本原因調査 v1

- 調査日：2026-08-18
- 指示者：利用者（Human）。文言「根本原因を探るのがまず最初」（2026-08-18 chat）
- 記録者：Claude
- 対象事象：観測record
  `records/development/2026-08-18-measurement-block-nondeterminism-observation-v1.md`
  （同一宣言のgrepが1回目10件・2回目22件・直接実行22件）

## 1. 機械検証で確定した事実

1. **tool内部の行落ちは除外**：`measurement_block.py`はstdoutを無加工で埋め込む実装で、行を
   加工・選別する経路が存在しない（fence長決定の走査は非破壊・切り詰めは上限100KB未達で不発動）。
   同一コード・同一宣言の2回目は完全出力を記録した。→ **1回目はgrep自身が10行しか返していない**
   （終了コード0・stderr空）。
2. **実行体は両回とも`/usr/bin/grep`（OS標準・BSD系）**：両回の生成物が`__pycache__/*.pyc`
   （バイナリ）を`-l`で列挙しており、これはOS標準grepの挙動（環境注入のugrep系wrapperは`-I`で
   バイナリ除外するため列挙しない）。venv環境の`shutil.which("grep")`も`/usr/bin/grep`
   【実測】。→ 実行体差は「shellとtoolの差」としては実在するが、**1回目と2回目の差の原因では
   ない**。
3. **無変異時は完全安定**：同一subprocess形で30回連続、全回23件（22＋観測record自身が検索語を
   含む自己言及増分）【実測】。
4. **変異直後窓の再現失敗**：「1 file追加→即walk走査」を、(a) 新設700 file dir で300回、
   (b) 実物`records/development`の複製（約1,500 entry）で300回——**計600回、欠落0**【実測】。
   1回目の実行だけが宣言file作成の約1秒後の走査だったという状況差は、再現実験では欠落を
   生まなかった。
5. 頻度：本日のtool経由grep実行十数回中、欠落は1回のみ。制御下630回で0回。

## 2. 結論

- 欠落は**我々のコード層の外**（OSのdirectory走査／file読取り層）で起きた**一過性の異常**である。
  tool論理は事実1で無実が確定し、実行体は事実2で同定済み、既知の再現手順は存在しない（事実3・4）。
- 候補としてはfts／APFSの一時状態・システム負荷・sandbox仲介などが残るが、userlandからの特定は
  本日の手段では不能。**「特定して直す」対象ではなく「検出して止める」対象**と判定する。

## 3. 調査の副産物（今後の測定の前提知識）

- **shellの`grep`とtoolの`grep`は同名別物**（環境注入のugrep系wrapper vs OS標準）。バイナリ扱い・
  ignore規則が系統的に異なるため、shell直接実行とtool実行の突き合わせには実行体の明示が要る。
  →guard設計の「実行体の絶対pathを生成物へ機械記録」がこれを恒久化する。

## 4. 帰結

完全性guard（二重実行の一致検査＝下層の一過性異常を我々の層で検出して止める）は、本調査により
**根因不明のまま放置する代替ではなく、根因の所在（下層・一過性・希少）に対する正しい対策類型**
であることが裏づけられた。事前走査
`records/development/2026-08-18-measurement-block-integrity-guard-prescan-v1.md`の設計のまま
実装へ進んでよい。
