## 確認範囲

先行レビューの止める指摘一件を直した変更点だけを確認してください。

1. 修正版の案Aが、新しいコード・設定・台帳を追加せず、既存機能と人の現行手順だけで済む最小案か。
2. 案Aの弱点が、単なる好みではなく、承認済みの機械接続と接続漏れ再発防止を満たさないという
   目的上の理由になっているか。
3. 案A、案B、案Cを比較した後も、案Cの採用候補が上位規則と方針採用判断に整合するか。
4. 案B、案C、入力・出力、警告境界、変更path、RED／GREEN、完了条件など、先行レビューで
   止める問題がなかった内容を変更していないか。

## 制限

- v1の変更していない節を再レビューしないでください。
- 実装方法の細部、将来拡張、追加機構、追加文書、追加試験を開始条件へ加えないでください。
- 本質から外れた過剰な修正案を出さないでください。
- 同じ原因は一件へまとめ、問題を見つけてもfileを修正しないでください。

止める指摘にできるのは、次の四つだけです。

1. 上位方針との矛盾
2. 必要な利用者承認の欠落
3. 誤った合否を生むことを示せる確認上の欠陥
4. 修正範囲または入力・出力形式の境界違反

## 出力形式

次だけを日本語で返してください。

1. 判定：`開始可`または`修正要`
2. 先行指摘：`解消`または`未解消`と根拠
3. 止める指摘：件数、四分類の番号、機械確認結果。同じ原因は一件
4. 報告不一致：件数と根拠
5. 試した反証：案Aが実際には新規実装を要しないか、または案Cの選択理由を崩す事実がないか
6. 未実施：変更、commit、外部送信、実装、試験実行の有無

止める問題が無ければ、余計な改善案を加えず`開始可`としてください。
