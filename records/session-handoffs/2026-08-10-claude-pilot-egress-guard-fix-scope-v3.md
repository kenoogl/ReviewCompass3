# 範囲固定 v3：group E修正 — RED定義の改定（既存testの契約更新を明示）

- 作成日：2026-08-10
- 作成者：Claude（Pilot）
- 状態：Humanの裁定待ち（本改定の承認またはRED定義の指示）
- 先行：scope v2（`4b52776`、範囲レビューv2 `verified`：`4e9ce51`）。v2は変更せず保持し、
  本v3が§6のRED定義と§5.4の件数条件のみを差し替える。他の節はv2のまま有効。

## 1. 改定が必要になった理由（RED着手前の実装契約の確認結果）

Human承認（2026-08-10「承認」＝risk `high`確定・資格情報3形式・64桁hex除外規則・
RED-1開始）を受けてRED-1に着手する前に、対象moduleの現契約を読解した。その結果、
**F-E1とF-E5の修正は現在の呼び出し契約そのものを変えなければ成立しない**ことが判明した。

| finding | 現契約 | 修正後に必要な契約 |
| --- | --- | --- |
| F-E1 | `run_egress_gate(approval_record=<dict>, now=<caller文字列>)`、`build_stage_one_runner`も同様 | 承認はHuman作成record **file**（path＋SHA-256）で渡す。有効期限はcaller提供`now`ではなく実時刻で判定するため、`now`引数を受け取らない |
| F-E5 | `redaction_hook=<任意のcallable>`を受け取り実行する | 許可実装の同一性を**実行前に**検査し、任意callableは実行せず拒否する |

現在の既存testは、いずれも**旧契約（欠陥のある契約）を写している**。

- `tests/test_egress_gate.py`：`approval_record=<dict>`・`now=NOW`・`redaction_hook=lambda`を
  用いる正例群（`TestEgressGate`の合格系、`TestStageOneSender`の2件を含む）
- `tests/test_egress_adversarial.py`：同じ旧契約でgateを呼ぶ反証群

したがって、scope v2 §6の「実装前は**新規testだけ**が失敗し、既存testは合格」は
本単位では満たせない。旧契約を写した既存testは、新契約へ更新した時点で（実装前は）
反証どおり失敗する。

## 2. 改定内容（v2 §6のRED定義の差し替え）

RED-1・RED-2は次を満たすこととする。

1. RED commitで変更するのは**test fileのみ**（v2 §6の表のpath指定は不変）。
2. RED commitには次の2種を含めてよい。
   - **新規の反証test**（F-E1〜F-E5、F-E6・F-E7）
   - **旧契約を写した既存testの契約更新**（新契約での呼び出しへ書き換える。
     検査している性質は弱めない。更新した既存testはEvidenceに**一件ずつ列挙**する）
3. 実装前の期待状態：**新規test＋更新した既存testだけが反証どおり失敗**し、
   **更新していない既存testは合格**、exit `1`。失敗理由が反証・新契約の不在で
   あることを機械確認してEvidenceへ記録する。
4. 既存testの**削除・検査性質の緩和は禁止**（呼び出し形の更新に限る）。緩和が必要と
   判断した場合は停止しHumanへ諮る。

## 3. 受入条件の差し替え（v2 §5.4）

- v2 §5.4「対象既存test 69 passed」→ **「§7の6 test file合計が、更新・追加後の全件で
  合格（件数はEvidenceに実測を記す）」**へ読み替える。公式全Test 1381 passed・
  status `passed`の条件は不変。
- v2 §5のその他（危険側の反証不成立、副作用の不在、正例の偽陽性不在、外部送信の不実施、
  上流・config・schema不変）は**すべて不変**。

## 4. 変更しないこと

- v2 §1〜§4、§6の表（commitごとの変更file）、§7の変更可能path、§8の停止条件、
  §9のHuman承認事項（既に承認済み）は不変。
- 本改定は**契約変更の可否**を確定するものであり、実装方式（許可実装の同一性検査の
  具体形など）は含まない。

## 5. Humanへの確認事項

1. 上記2・3の改定（RED commitに既存testの契約更新を含めることの承認）。
2. 承認が得られない場合の代替（例：契約を変えない範囲へ修正を縮小する、あるいは
   本単位を中止する）の指示。
